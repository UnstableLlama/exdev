## Reviewer-only hindsight (must not reach any teacher packet)

Upstream commit `3a7b4895e45b` "Fix DeciLM n_heads_in_group attn config" (walk position 44, committed 13 hours later) changes the line this commit adds from

`num_kv_heads = cfg_attn["n_heads_in_group"]` to `num_kv_heads = config.num_q_heads // cfg_attn["n_heads_in_group"]`.

So the task commit ships a wrong key/value head count whenever the group size differs from the number of groups. The draft reports the line exactly as written ("attention receives n_heads_in_group as num_kv_heads") and neither endorses nor questions it.

How I learned it: `git log` on `decilm.py` past the cutoff. That is later evidence. Per the retrospective policy it belongs in the defect ledger when the walk authors the fix, extracted from that explanation, and it must not be injected into this entry, into the entries for commits 40 to 43, or into guidance.

Was it catchable without hindsight? Partly. The field name says "heads in a group" and the parameter wants "number of key/value heads"; those are different quantities by name alone, and the draft had `num_q_heads` in view. A suspected finding on the naming mismatch would have been legitimate. Confirming it needed a reference configuration or implementation, and none was in the evidence catalog, which the draft says plainly.
