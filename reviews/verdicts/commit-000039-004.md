## The incorrect claim

The draft says:

- Ultra-253B-CPT "uses ... 128 query heads and 16 KV heads for active attention", and Ultra-253B "has the same ... active KV-head count".
- Super-49B uses "64 query heads and eight KV heads".

Both are labelled source and cite only the configuration files. Those files do not state a key/value head count. They have a field `n_heads_in_group`, whose value is 16 for Ultra and 8 for Super. The draft has read that field as the head count, which is what the code under review does, and reported the code's reading as a fact about the models.

The tensor headers attached in the same packet say otherwise for Ultra. Its key and value projection tensors are 1,024 wide in every active block; at a head dimension of 128 that is 8 heads, not 16. For Super the stored width also gives 8, so that sentence happens to be true.

The guidance for this run says the rule "applies to configuration files only; read tensor headers as needed to support claims". A per-model head count is a dimension claim. No header was read. The draft's own limits say "Configuration comparisons do not establish agreement with checkpoint tensor shapes", which is right, and is the reason the head-count sentences should not have been stated as source.

This is judged on the same terms as any entry: a source-labelled statement contradicted by eligible evidence in the packet. It is the first rejection on correctness in this walk.
