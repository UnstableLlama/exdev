## Why thin

The guidance says: read every model's configuration before calling something corroborated, name the ones read, and "if any was not read, say so and limit the claim to those that were". The draft used that last clause: it read the 51B configuration, listed the other eight as unread and made no cross-model claim. That complies with the sentence as written and defeats its purpose.

What the unread configurations would have added, from the attached bundle:

| Model | Query heads | Group sizes in use | Linear-replacement blocks |
|---|---|---|---|
| Super-49B | 64 | 8 only | none |
| 51B (the one read) | 64 | 8, 16, 32, 64 | 18 |
| Ultra-253B | 128 | 16 only | none |
| Ultra-253B-CPT | 128 | 16 only | none |

So a complete entry would say which of the models attached for this commit the new code can construct and load, per model. The draft cannot say that, and its Impact line ("does not establish compatibility with every Nemotron checkpoint") is weaker than what the evidence in its own packet supports.

It also matters that the choice of model was effectively made by listing order. Attempt 002 read the model listed first in its catalog (Super) and saw nothing wrong; this attempt read the model listed first in the index (51B) and found two problems. An entry should not depend on that.
