## The two findings

**plain-mlp-allocation-interface (suspected, defect).** Holds. `TransformerBlock.allocate_q` now reads `self.mlp.ups` and `self.mlp.downs` for any MLP, and the unchanged `MLP` class defines only `up` and `down`. The draft checked reach: all four model builders in the tree construct `GatedMLP`, so no shipped model hits it. Right strength.

**ungated-list-strategy-key (suspected, defect).** Holds. In the new list branch for an ungated MLP the code appends the list itself (`keys += [m]`) where the gated branch appends the wildcard string. The final dictionary would be keyed by lists. Unreachable today for the same reason as above, which the draft says.

Both are real slips in code paths that nothing currently exercises. Well found.

## What the draft misses (reviewer reading of the same source; unexecuted)

1. **Attention is quantised once per slice.** For a sliced block, each pass of the slice loop calls `module.load(device, load_slice=n)`. `Attention.load` accepts the keyword and calls `super().load(device)`, so the attention projections are loaded from disk again on every pass. The list of layers to quantise is every `Linear` with a `qmap` and a device, which includes them, and the block is unloaded at the end of each pass. So a block with attention and an N-slice MLP captures and quantises its four attention projections N times, each result overwriting the last in the collected tensors. The draft's "repeated module loading and forward passes" does not convey this. I am confident in the reading but did not run it.
2. **It changes the standing of three ancestor findings**, none of which the teacher read (zero ancestor reads this run):
   - Commit 47's CPU-bias finding: the converter now unloads and reloads the converted module from the collected tensors, and the memory branch of `get_tensor` moves each tensor to the device. A bias left on CPU by conversion no longer reaches the state-advance forward pass.
   - Commit 53's default-staging finding: `GatedMLP` now passes the full sizes, so an unsplit gated MLP's linears are no longer CPU-staged by default. Attention projections and output heads still are.
   - Commit 53's padding-before-slicing finding: this commit is the first caller that requests slices. Slice widths are multiples of 128 except the last, which is aligned only if the whole intermediate size is. The draft notes the unaligned remainder in its limits but does not connect it to the failure that ancestor entry describes.
3. **The reference error is still computed for sliced modules** from states captured with a single slice active, then discarded in favour of "N/A". Harmless, but the entry says only that the display changes.
4. **The `source = q_tensors` keyword on the reload call is consumed by nothing.** The mechanism is `set_new_tensors`, as the draft says; the keyword is inert.
