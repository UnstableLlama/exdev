## What is decided (my reading, stated so the user can correct it)

A new kind of attempt, a **revision**, may follow a rejection or a declined replacement.

1. Inputs: the same immutable packet; the teacher's own previous annotation for that position (the rejected
   attempt's draft); that attempt's tool results, so checks already made need not be repeated; and the
   reviewer's pointer-only coverage request. Nothing else: no verdict text, no reviewer facts, no ledger
   material, no other attempt's prose.
2. The teacher writes the complete entry again as its own work. It keeps what the earlier attempt
   established, adds what the coverage request asks it to examine, and may correct itself. Every statement
   kept must still carry a valid citation, to a call in the earlier transcript or a new one.
3. Nobody else edits prose. The author and the reviewer still never change an entry's text. The rejected
   attempt stays on disk as history, unchanged.
4. Labelling: the run is recorded as a revision of the named attempt and as reviewer-assisted. The request
   says so, binds both transcripts, and lists what was kept, added and removed against the earlier attempt.
5. Review standard is unchanged. A revision that drops true content of the attempt it revises is declined.
6. Fresh attempts remain available: the reviewer may ask for one where the earlier draft is misleading
   enough that anchoring on it would hurt. One revision per rejection; a second failure needs a request.
7. Scope stays ancestor retrieval only; canonical and training stay false.

## What happens next

The author files an implementation request for the revision mode (prompt text, how the earlier transcript is
supplied and cited, validation, replay, provenance fields, request template) with tests. The reviewer reviews
it before any revision is run. Until it is accepted, rejections keep getting fresh assisted attempts; the
255/003 attempt already requested stays a fresh one.
