## The request's specific questions

- **Accepted dtypes.** After this commit both constructors accept None, half, and float (cast to half). Anything else is stored unchanged with no check.
- **What else can arrive.** `SafetensorsCollection.get_tensor` converts BF16 to half unless `allow_bf16` is set, and `linear.py` does not set it for biases, so a BF16 bias arrives as half. The loader's dtype table has only F16, BF16, F32, I16 and I32, so the remaining possibilities are integer biases.
- **Explicit failure or later.** Not explicit any more. On the EXL3 path an unexpected bias dtype would become the output dtype, because the forward casts `x` to it. On the dense path it would be added in place into a half tensor. Whether either then fails was not executed by the draft or by me. The draft says such biases "pass this constructor check unchanged" and that compatibility is not established, which is right; it does not mention that the EXL3 forward adopts the bias dtype.
- **Conversion timing.** Before this commit the assertion sat in the `LinearEXL3` constructor, which `convert_exl3` calls after `quantize_exl3` returns. So the failure in issue 11 came after the layer's quantization work had been done. The draft says the assertion "could interrupt conversion" without the timing.
