## Must fix before any canonical use (not blocking ancestor retrieval)

1. The draft describes `first_block_idx` from the Llama layout only. The base `Model` sets it to `None`, and the new `idx >= model.first_block_idx` comparison would raise for any model class that leaves it unset. In the parent tree Gemma2 and Phi3 set it and Mistral and Qwen2 inherit Llama's, so no shipped class is affected, but a canonical entry should say that it checked every model class, not one.
2. On a resumed job the clock restarts when the loop passes the first block, which happens during the skip, so elapsed time covers only modules processed in this session. The draft says the reset still happens on resume but does not state this consequence. It is correct behaviour; say so plainly.
