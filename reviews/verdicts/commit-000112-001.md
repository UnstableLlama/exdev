## Residual dtype (checked after the first version of this verdict)

`Embedding.__init__` has `out_dtype = torch.float` as its default and applies it in `forward` (`embedding.py` lines 18 and
74); converting float32 weights to half on load affects storage only. The Qwen3 builder passes no override, so the
residual stream `x` is float32. The in-place `x += y` therefore keeps a float32 MLP result at full width. Before this
commit the down projection produced half and the add widened an already rounded value; after it the value reaches the
residual unrounded. This is the mechanism behind the entry's "rather than merely widening an already-rounded MLP
result".

An earlier version of this file guessed the residual was probably half. That guess was wrong and is withdrawn.
