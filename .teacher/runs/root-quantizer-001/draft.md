- [EXL3: Hessian feedback, procedural trellises and packed transforms](#quantizer)

## Problem

EXL3 addresses the tension between high-dimensional low-bit quantization and inexpensive decoding: ordinary vector codebooks grow exponentially, while generic trellises require sequential decoding and stored lookup structures. [source; call_38474e81eb4d4902be34086a198ff1d9, call_0662d87f7f1149108a96331477e4c822]

## Reasoning

The quantizer combines Hessian-derived block error feedback with QTIP-style trellis coding, but adapts the preprocessing, numerical representation and packing rather than reproducing the complete QTIP pipeline. [source; call_3343ffc4a9c343db8269a3934053917f, call_67dfb342f2d34e3a8f06fc97652bf622, call_493042135bd6483b8f08d7a295a0a622, call_38474e81eb4d4902be34086a198ff1d9]

## Impact

For an aligned k-by-n matrix, the emitted tensors require K bits per weight for the trellis plus 16(k+n) bits for signed channel scales, excluding bias and container metadata. No learned codebook is stored. [inference; call_3343ffc4a9c343db8269a3934053917f, call_0fddf6c696c64c2eaf9aa5eaea70422d]

## Source Notes

The relevant QTIP comparison is its lookup-free 3INST variant. The pinned reference also supports LUT and HYB codebooks; its README describes optimized inference kernels for HYB with V=2, not the V=1 procedural format used here. [source; call_e5636fe740ac4f7292b4a7a1cdc3fa95, call_e78405b9364340c38c850efda04f759d, call_0fddf6c696c64c2eaf9aa5eaea70422d]

## EXL3: Hessian feedback, procedural trellises and packed transforms

Pipeline and data flow. Linear.capture_H flattens calibration activations and accumulates XᵀX in FP32, counting activation rows. Layers sharing a qmap reuse the capture, with only its first layer accumulating samples. Linear.convert_exl3 passes FP32 weights to quantize_exl3, preserves bias, and replaces the original layer with LinearEXL3. The quantizer works in (input_features, output_features) orientation, prepares H and scales, searches a global scale, runs LDLQ and trellis quantization, optionally reverses the transforms, and emits suh, svh and trellis. [source; call_1e67ee7b44e046f09d8c86b46c549388, call_3343ffc4a9c343db8269a3934053917f]

Hessian preparation. finalize_capture_H divides the accumulated Gram matrix by the sample count and adds sigma_reg × mean(diag(H)) to its diagonal, defaulting to 0.025. It samples input signs, applies them on both sides of H, and applies normalized 128-element Hadamard blocks. block_ldl then constructs H = LDLᵀ from a Cholesky factor: each 16-by-16 diagonal factor defines a D block, and its inverse normalizes the corresponding block column of L. Diagonal blocks are explicitly replaced by identities; finalize_capture_H removes their diagonal ones to obtain the strictly block-lower feedback matrix. D is discarded. [source; call_3343ffc4a9c343db8269a3934053917f]

BlockLDLQ mapping. block_ldl and ldlq implement the decomposition-and-feedback mechanism of QuIP# v2 §4.1, using the reverse traversal and H=LDLᵀ convention made explicit in QTIP v3 Algorithm 5. For a current input-row block I, ldlq quantizes W[I] + L[J,I]ᵀ(W[J]−Wq[J]) over already processed rows J. The implementation splits that correction between an inner-buffer product and prod_cache, then updates the cache with b_Lᵀ(b_weight−b_weight_q). This is the same algebraic recurrence as the pinned lib/algo/ldlq.py::LDLQ after accounting for weight orientation, but with different storage, permutation and device handling—not a claim of identical numerical output. [source; call_3343ffc4a9c343db8269a3934053917f, call_f43984cb75a74414ba04a7332a2c6d1e, call_5683abc31c09459e992b5c791d4e87a3, call_577f9a82aa3a409ea5146d4f3afe446a]

Why two levels of quantization are needed. The Hessian proxy includes interactions between input channels and is not an additive sequence distortion that Viterbi can minimize directly. EXL3 therefore uses 16 input channels for each feedback step, but joins them with 16 output channels into a 256-weight trellis sequence. This matches QTIP Algorithm 5's Tx=Ty=16 construction: high-dimensional rounding without making the LDL block size 256. The local trellis minimizes squared reconstruction error after compensation; it does not globally minimize the original layer loss. [source; call_3343ffc4a9c343db8269a3934053917f, call_67dfb342f2d34e3a8f06fc97652bf622, call_3b1aa5f9599c4f70a36d9b2f3374c7c7, call_577f9a82aa3a409ea5146d4f3afe446a]

Transform mapping and adaptation. preapply_had_l and preapply_had_r supply the normalized Hadamard operations underlying QuIP# Algorithm 3, IP-RHT, and QTIP §2.1. EXL3 fixes both transform widths at 128 rather than mixing each entire matrix dimension. quantize_exl3 also adds signed RMS rescaling: normalize output-channel RMS values to mean approximately one, divide weights by these signed scales, transform the output axis, then compute input-channel RMS values and divide by signed input scales before transforming the input axis. The input scale includes the constant −1.24371088. This is an adaptation of incoherence processing, not an exact implementation of sign-only IP-RHT or QuIP#'s learned-scale fine-tuning. [source; call_3343ffc4a9c343db8269a3934053917f, call_12f7ed73997c4f4eac17b518e817407e, call_5683abc31c09459e992b5c791d4e87a3, call_0662d87f7f1149108a96331477e4c822]

Scale selection trades conversion work for codebook coverage. g_scale_mse_gridsearch runs the actual tile quantizer on sampled tiles, first across 12 scales from 0.25 to 1.075 and then across 16 nearby scales. It compares MSE after undoing each trial scale. The chosen factor multiplies the transformed weights and is absorbed inversely into su, so it needs no separate stored scalar. g_scale_outliers_binsearch is an implemented but inactive alternative targeting an outlier fraction above magnitude 3.9. The active sampler's inner loop uses width rather than its loop variable w, so it repeats each selected tile instead of sampling distinct neighboring offsets. [source; call_3343ffc4a9c343db8269a3934053917f]

Interpretation of the numerical objective. H and L are finalized using input signs and Hadamard transforms before the per-weight-matrix RMS scales are computed. They are not subsequently conjugated by those scale magnitudes, and output scaling is not included in the reported proxy. Consequently, sum(H × EEᵀ)/sum(H × WWᵀ), as computed here in transformed coordinates, should be treated as a relative surrogate rather than an exactly invariant original-layer output error. Reusing one factorization across related projections avoids additional factorizations, but is not the same mathematical setup as the papers' loss-preserving orthogonal transform. [inference; call_3343ffc4a9c343db8269a3934053917f, call_12f7ed73997c4f4eac17b518e817407e]

Trellis search mapping. Python quantize_tiles delegates to CUDA quantize_tiles_kernel, specialized for K=1…8, L=16 and V=1. For each position it keeps costs for 2^(16−K) overlap states, enumerates 2^K candidate full codewords, adds the squared error from decode_pcb_f_diff, and records the cheapest predecessor. Backtracking reconstructs each 16-bit codeword as (previous_overlap << K) | current_overlap. This is a reduced-overlap-state formulation of the Viterbi recurrence in QTIP §2.3 and the pinned bitshift_codebook.update/viterbi methods. EXL3 computes procedural values during search and keeps FP32 costs; the reference precomputes reconstruction values and quantize converts its input sequence to FP16. [source; call_3343ffc4a9c343db8269a3934053917f, call_67dfb342f2d34e3a8f06fc97652bf622, call_e5636fe740ac4f7292b4a7a1cdc3fa95, call_0662d87f7f1149108a96331477e4c822]

Tail-biting mapping and qualification. The kernel's forward/backward lambdas follow QTIP v3 Algorithm 4 and bitshift_codebook.quantize: solve a sequence rotated by 128 positions, extract an overlap near its middle, then solve the unrotated sequence with that overlap fixed at both boundaries. This removes the extra initial-state bits without exhaustively searching cyclic boundaries. There is, however, a source-level discrepancy: forward writes the latest costs to temp_costs, while argmin_cost reads temp_costs_inc. The first-pass terminal selection therefore reads the preceding-position buffer. The two-pass structure corresponds to the paper, but exact reference-equivalent path selection is not established. [source; call_67dfb342f2d34e3a8f06fc97652bf622, call_e5636fe740ac4f7292b4a7a1cdc3fa95, call_3b1aa5f9599c4f70a36d9b2f3374c7c7]

Exact procedural-code correspondence. decode_3inst implements QTIP v3 Algorithm 2 and the pinned decode_3inst formula: multiply by 89226354, add 64248484 with uint32 wraparound, mask with 0x8fff8fff, XOR with 0x3b603b60, reinterpret the two halves as FP16 and add them. decode_pcb selects this implementation; decode_3inst_2 evaluates two codes with half2 arithmetic. This is exact correspondence of constants and operations, not an executed bitwise-equivalence result. The values are deterministic, approximately Gaussian code values—not independent Gaussian samples. decode_2mad is present but disabled; its scaling and integer intermediate handling differ from the pinned decode_2mad, so it should not be described as an exact port. [source; call_0fddf6c696c64c2eaf9aa5eaea70422d, call_e5636fe740ac4f7292b4a7a1cdc3fa95, call_0662d87f7f1149108a96331477e4c822, call_3b1aa5f9599c4f70a36d9b2f3374c7c7]

Packing is a format adaptation. ldlq applies tensor_core_perm before search, then undoes it only for reconstructed floating-point weights; indices remain in tensor-core order. Python pack_trellis allocates 16K int16 words per 256-weight tile. CUDA pack_trellis_kernel stores only each codeword's low K bits, using 16 aligned spans and swapping paired 16-bit words. unpack_trellis_kernel recovers overlapping 16-bit windows through cyclic addressing and funnel shifts. This uses QTIP's bitshift/tail-biting principle, but differs from reference bitshift_codebook.pack_trellis, which starts with a full initial codeword and removes the repeated tail. Shared principles do not imply compatible serialized bytes. [source; call_3343ffc4a9c343db8269a3934053917f, call_493042135bd6483b8f08d7a295a0a622, call_e5636fe740ac4f7292b4a7a1cdc3fa95, call_3b1aa5f9599c4f70a36d9b2f3374c7c7]

Transform construction versus execution. get_hadamard/get_hadamard_dt cache matrices obtained from stored constants, Sylvester doubling, or the paley/paley2 wrappers around C++ had_paley/had_paley2. These are matrix-construction utilities, not trellis algorithms. The active conversion path requests normalized 128-by-128 matrices and multiplies in FP32. Runtime had_r_128 instead launches hadf_r_128_kernel: a four-element butterfly followed by five warp-shuffle stages, normalization by 1/√128, and conversion back to FP16. Its optional pre_scale is multiplied in half2 before conversion to float. The separate all-half hadh_r_128_kernel is not the kernel selected by this wrapper. [source; call_c51233f913904848aeb2f50897e99962, call_f908905bfc464d7987303f980907a948, call_3343ffc4a9c343db8269a3934053917f, call_334f8e0108544c358b6b804e3ac5dde5]

Reconstruction closes the transform chain. Writing Bk and Bn for the block Hadamard matrices, the stored representation reconstructs W approximately as diag(su) Bk Q Bn diag(sv). LinearEXL3.forward correspondingly scales and transforms input activations, multiplies by the inner quantized matrix, transforms outputs and applies svh before bias. This is the transformed-multiply structure of QuIP# Algorithm 2 and QTIP BitshiftLinear.forward, adapted to EXL3 scales and block transforms. The runtime defaults to reconstructing the inner matrix for batches of at least 32 rows; smaller batches use exl3_gemm. Scale normalization explicitly aims to reduce GEMM/output-transform overflow, but half-precision scales and prescaling remain numerical constraints. [source; call_9daa6ed7e921450f87c971bfbff2e5a3, call_3343ffc4a9c343db8269a3934053917f, call_334f8e0108544c358b6b804e3ac5dde5, call_12f7ed73997c4f4eac17b518e817407e, call_e5636fe740ac4f7292b4a7a1cdc3fa95]

Principal tradeoffs. Procedural 3INST avoids a lookup table and its cache traffic, whereas QTIP's HYB alternative offers tunable codebook entries at the cost of table storage. EXL3's search still evaluates 2^16 candidates per sequence position: changing K trades overlap-state count against candidate fan-in, while predecessor storage scales with 256 × 2^(16−K) per tile. The Python wrapper reserves scratch for 128 tiles. For matrices above 5×10^8 elements, conversion moves weights and collected outputs to CPU, trading transfers and synchronization for lower GPU storage, but retains a full GPU prod_cache. Fixed 128-wide transforms simplify execution while mixing fewer coordinates than full-dimensional RHT; neither the papers' quality results nor their speed measurements establish EXL3's resulting tradeoff. [inference; call_3343ffc4a9c343db8269a3934053917f, call_67dfb342f2d34e3a8f06fc97652bf622, call_0fddf6c696c64c2eaf9aa5eaea70422d, call_3b1aa5f9599c4f70a36d9b2f3374c7c7]

## Uncertainty and limits

No CUDA execution, packing round-trip test, numerical comparison or model evaluation was performed; source correspondence does not establish measured accuracy or throughput.

The two-pass tail-biting procedure is an approximation, not a search over every possible cyclic boundary. The CUDA cost-buffer discrepancy described below also prevents claiming exact equivalence to the reference implementation.

Full-matrix incoherence guarantees and original-coordinate proxy-loss invariance cannot be transferred directly to EXL3's block-local transforms and separately computed channel scales.

The path assumes usable calibration statistics, successful Cholesky factorization, aligned dimensions and finite representable scales. Its small FP32 epsilon additions do not establish robustness after FP16 scale storage.
