## Problem

The model layer must translate architecture-specific configuration and checkpoint names into shared attention, MLP, normalization and output modules. [source; call_4e573b2a1bff4d1596a849083842f3fb, call_2bf97cffb54c404db531d664bc197d62, call_9d20ee4c565847cabb6c03320692f7de, call_4887351d9a60417a885bfddf6d6a5753]

## Reasoning

The implementation shares Llama construction with Mistral and Qwen2, while explicitly adapting Phi3's fused checkpoint projections and Gemma2's normalization, scaling and softcapping. [source; call_1d4523c7820144c2b2d2ca2288906842, call_547713695a844166803065afbd7898b5, call_9d20ee4c565847cabb6c03320692f7de, call_4887351d9a60417a885bfddf6d6a5753]

## Impact

Five architecture names are registered, but registration and matching tensor dimensions do not establish full reference-model equivalence: sliding-window configuration has concrete mapping gaps. [inference; call_4e573b2a1bff4d1596a849083842f3fb, call_01763895acc1474281f6e06d62047559, call_1e2940c5974e456483b2f31163df6f8b, call_d20039afd5964f91bbe3229fbc2f6f7c, call_2bf97cffb54c404db531d664bc197d62, call_9d20ee4c565847cabb6c03320692f7de, call_4887351d9a60417a885bfddf6d6a5753]

## Architecture dispatch and checkpoint-to-module mapping

Dispatch uses config.json's single architectures entry, not model_type or remote auto_map code. Config.from_directory rejects missing, multiple or unknown architecture declarations and selects one of LlamaConfig, MistralConfig, Qwen2Config, Phi3Config or Gemma2Config. Model.from_config then instantiates config.model_class. A subtle distinction is that MistralConfig and Qwen2Config inherit LlamaConfig's assignment of LlamaModel: their registered model subclasses are thin wrappers, but the normal factory actually constructs LlamaModel for both. [source; call_4e573b2a1bff4d1596a849083842f3fb, call_3ac63e7f2f9b47a19663bc5481cec4f4, call_c095ad5e75eb4035965bed75cef0f534, call_2bf97cffb54c404db531d664bc197d62, call_1d4523c7820144c2b2d2ca2288906842, call_547713695a844166803065afbd7898b5]

Configuration loading establishes the tensor collection, vocabulary and special-token IDs before architecture construction. EOS may be an integer or list; the list is retained while its first element becomes eos_token_id. Architecture configs map hidden_size, intermediate_size, layer count, query/KV head counts and RMS epsilon; missing KV-head count defaults to query-head count, and absent head_dim falls back to hidden_size // num_attention_heads. read_dict accepts integer-to-float conversion, so Gemma's integer query_pre_attn_scalar is accepted. Shared RoPE settings carry theta, scaling, partial-rotary factor and context limits with NEOX style. Phi3 alone overrides override_dynamic_seq_len to update the RoPE override before model construction. [source; call_3ac63e7f2f9b47a19663bc5481cec4f4, call_dd3f328daecd496386cfbd605b64d41b, call_2bf97cffb54c404db531d664bc197d62, call_9d20ee4c565847cabb6c03320692f7de, call_4887351d9a60417a885bfddf6d6a5753, call_c6430d9a6ea0416c9da7e20dc569d6b8]

The common model sequence is model.embed_tokens, one TransformerBlock per model.layers.i, model.norm, then lm_head. Llama-style blocks apply input_layernorm before attention and post_attention_layernorm before the gated MLP, with a residual addition after each branch. Attention maps q_proj/k_proj/v_proj/o_proj; the MLP maps gate_proj/up_proj/down_proj. With hidden width H, head width D, query heads Q, KV heads K and intermediate width I, checkpoint matrix shapes are [QD,H], [KD,H], [KD,H], [H,QD], [I,H], [I,H], [H,I]. This permits attention width QD to differ from residual width H, as Gemma requires. [source; call_2bf97cffb54c404db531d664bc197d62, call_c021c68c16074c79924f51bc562dbd04, call_dca98a08d5d946fc90014a026ac2cfee, call_e7afe3958bcb45a5b7b0a50fc903c63e, call_db291d1f84594376a6f5af18e14423c8]

TinyLlama supplies the straightforward Llama example: 22 layers, H=2048, I=5632, 32 query heads and four KV heads. Its BF16 header contains separate [2048,2048] Q/O matrices, [256,2048] K/V matrices, [5632,2048] gate/up matrices and [2048,5632] down matrices. Both embedding and untied output weights are [32000,2048]; layer norms and final norm have width 2048. The config selects SiLU, RMS epsilon 1e-5, theta 10000 and a 2048-position limit, matching the fields consumed by LlamaConfig. [source; call_3d439fb0c082421ba62000aa360d8048, call_1dd1bb7012a448d0bda2128a910a3c64, call_2bf97cffb54c404db531d664bc197d62]

Mistral reuses the same construction and naming. The pinned 7B checkpoint has 32 layers, H=4096, I=14336, 32 query heads and eight KV heads; its headers contain Q/O [4096,4096], K/V [1024,4096], gate/up [14336,4096], down [4096,14336], and separate [32000,4096] embedding/head weights. Sharding is not a layer boundary: layer 22's attention tensors are in shard one while its norms and MLP are in shard two. SafetensorsCollection indexes individual tensor names across all files, so constructors need no shard-specific logic. [source; call_1d4523c7820144c2b2d2ca2288906842, call_01763895acc1474281f6e06d62047559, call_520039ff856744319aa2926d9386ffd9, call_8c1d2ace022a449c8f2528f28a4e0f4b, call_554416c16d104a6ca72e3abb669fff86]

Qwen2.5-0.5B declares Qwen2ForCausalLM and fits the shared Llama layout with 24 layers, H=896, I=4864, 14 query heads and two KV heads. Its header additionally contains q_proj.bias [896] and k_proj.bias/v_proj.bias [128], but no O or MLP biases. Linear.load_fp16 retrieves each optional .bias rather than requiring a separate Qwen attention implementation. The config supplies theta 1000000, RMS epsilon 1e-6 and tied embeddings; the header contains model.embed_tokens.weight [151936,896] and no lm_head.weight. LlamaModel provides an embedding fallback for the output layer when tying is enabled. This is a loading fallback, not proof of shared runtime storage. [source; call_547713695a844166803065afbd7898b5, call_2be10d0a65f64354b457a45535cfa865, call_e094c1de1e71473cb3d47001b36d664b, call_2bf97cffb54c404db531d664bc197d62, call_bb207cd3479145ecbc9812227a226b51]

Phi3 retains separate logical Q/K/V and gate/up modules while accepting fused source tensors. Its pinned checkpoint has 32 layers, H=3072, I=8192 and 32 query/KV heads. Attention.__init__ assigns consecutive Q, K and V row ranges within self_attn.qkv_proj.weight [9216,3072]; GatedMLP.__init__ assigns gate then up ranges within mlp.gate_up_proj.weight [16384,3072]. Linear.load_fp16 first tries the separate logical weight, then slices the fused weight along its first axis and makes the slice contiguous. O remains [3072,3072], down [3072,8192], and embedding/head [32064,3072]. This adaptation preserves common execution and conversion interfaces rather than adding a fused-projection execution path. [source; call_9d20ee4c565847cabb6c03320692f7de, call_1e2940c5974e456483b2f31163df6f8b, call_0b1cc4fc0abf46c785334a9865bad356, call_7b6567aea2d74222bbed97a2a36f4788, call_c021c68c16074c79924f51bc562dbd04, call_dca98a08d5d946fc90014a026ac2cfee, call_bb207cd3479145ecbc9812227a226b51]

Gemma2 requires more than renamed tensors. The mirror has 26 layers, H=2304, I=9216, eight query heads, four KV heads and explicit D=256. Accordingly Q is [2048,2304], K/V [1024,2304] and O [2304,2048]; deriving D from H/Q would be wrong. Each layer has four norm vectors: input_layernorm, post_attention_layernorm, pre_feedforward_layernorm and post_feedforward_layernorm. Gemma2Model places post-norms before the branch residual additions, requests float outputs from those post-norms, and passes constant_bias=1 to every RMSNorm. RMSNorm's reference expression multiplies normalized activations by weight+1 rather than weight. Embedding normalization multiplies by sqrt(H), and the MLP selects the GELU multiplication kernel. [source; call_d20039afd5964f91bbe3229fbc2f6f7c, call_db291d1f84594376a6f5af18e14423c8, call_4887351d9a60417a885bfddf6d6a5753, call_b5211fb2ddef4eaea50ef4dc9f502f74, call_76f73b70e78a4f67a77364d0475a299c, call_e7afe3958bcb45a5b7b0a50fc903c63e, call_dca98a08d5d946fc90014a026ac2cfee]

Gemma's attention scale is query_pre_attn_scalar**(-0.5), using the mirror's 256 rather than the implementation's fallback 224. Attention softcap 50 is passed to FlashAttention; output softcap 30 is applied by Linear through the native transformation c*tanh(x/c), a smooth saturation rather than hard clipping. Gemma2Model always offers model.embed_tokens as the head's alternate key, consistent with the mirror header's sole [256000,2304] vocabulary matrix and absent lm_head. The SDPA alternative explicitly rejects nonzero attention softcapping, so it is not an interchangeable Gemma execution path. [source; call_d20039afd5964f91bbe3229fbc2f6f7c, call_db291d1f84594376a6f5af18e14423c8, call_4887351d9a60417a885bfddf6d6a5753, call_c021c68c16074c79924f51bc562dbd04, call_bb207cd3479145ecbc9812227a226b51, call_e1036111cba245d6ba179bfe10ee33b8]

Window configuration limits the apparent architectural correspondence. Mistral's pinned sliding_window=4096 and Phi3's sliding_window=2047 are neither read nor passed by their constructors, leaving Attention's default -1. Gemma2Model contains an even-layer window/odd-layer unrestricted pattern, but Gemma2Config reads sliding_window_size; the mirror supplies sliding_window=4096, so both parities receive -1. FlashAttention receives that value as window_size. Qwen's pinned use_sliding_window=false makes its unwindowed construction consistent on this particular setting, not evidence of support for windowed Qwen variants. [source; call_01763895acc1474281f6e06d62047559, call_1e2940c5974e456483b2f31163df6f8b, call_d20039afd5964f91bbe3229fbc2f6f7c, call_2be10d0a65f64354b457a45535cfa865, call_2bf97cffb54c404db531d664bc197d62, call_9d20ee4c565847cabb6c03320692f7de, call_4887351d9a60417a885bfddf6d6a5753, call_c021c68c16074c79924f51bc562dbd04]

A successful standard-library Python check reconstructed projection dimensions from transcribed config/header metadata. Head dimensions were 64, 128, 64, 96 and 256 for TinyLlama, Mistral, Qwen, Phi3 and Gemma respectively; query-heads-per-KV-head were 8, 4, 7, 1 and 2. Structural tensor counts matched 201, 291, 290, 195 and 288. Phi3 ranges [0,3072), [3072,6144), [6144,9216) and [0,8192), [8192,16384) covered their fused row axes exactly without overlap. Gemma's embedding multiplier evaluated to 48 and attention scale to 0.0625. These checks use Python integers and scalar floating point, not GPU tensors or BF16/FP16 arithmetic. [execution; call_69797b953d3d410fa3df7abadbf457b6]

Architecture definitions expose the same logical matrices to conversion and inference. Their qmap prefixes become shared Q/K/V capture groups and gate/up capture groups, while output projections have separate groups; Linear.capture_H accumulates XᵀX only for the group's first logical key. The head uses head_bits independently of ordinary bits. Linear.load chooses EXL3 tensor groups before ordinary weights, and Phi3's fused fallback exists in the ordinary-weight path. All inspected reference headers store BF16, but SafetensorsCollection.get_tensor defaults to converting BF16 to FP16, so checkpoint dtype is not a claim about runtime arithmetic. [source; call_2bf97cffb54c404db531d664bc197d62, call_9d20ee4c565847cabb6c03320692f7de, call_4887351d9a60417a885bfddf6d6a5753, call_c021c68c16074c79924f51bc562dbd04, call_dca98a08d5d946fc90014a026ac2cfee, call_bb207cd3479145ecbc9812227a226b51, call_554416c16d104a6ca72e3abb669fff86, call_1dd1bb7012a448d0bda2128a910a3c64, call_520039ff856744319aa2926d9386ffd9, call_e094c1de1e71473cb3d47001b36d664b, call_0b1cc4fc0abf46c785334a9865bad356, call_db291d1f84594376a6f5af18e14423c8]

The model boundary also supplies execution and cache lifecycle hooks. Architecture prepare_inputs methods retain input_ids in params and invoke prepare_for_attn. Model.forward moves state through each module's device preparation and forward method; Model.prefill stops at last_kv_module_idx, with the final block skipping its remaining residual/MLP work after attention. model_init.init constructs config, model and optional cache before loading, then optionally creates the tokenizer. Model.load supports a single device or sequential module autosplitting with dummy forwards and out-of-memory retry; tensor parallel loading explicitly remains unimplemented. ## Uncertainty and limits

No checkpoint payloads, GPU model execution, output-equivalence tests or performance measurements were examined. The successful Python check validates metadata arithmetic and row-range coverage only.

Tensor headers establish names, shapes and stored dtypes, not the semantic ordering of Phi3's fused weight rows or numerical equivalence to reference implementations.

Mistral and Phi3 do not propagate their pinned sliding_window values; Gemma2 reads sliding_window_size rather than the mirror's sliding_window. The effect on generated outputs is unmeasured.

Gemma mirror equivalence to gated upstream google/gemma-2-2b remains unverified. These five checkpoint examples do not establish compatibility with every variant bearing the registered architecture names.
