## Problem

The initial implementation needs reusable transformer components that connect architecture-specific tensor names to attention, residual computation, quantized projections and KV-cache storage. [inference; call_7da38eeaee9e439d95a96fcf2314bc71, call_15326ae372f14506841a44dbf3171ec0, call_fce3285be7144390b6bcf32cd83aad28]

## Reasoning

The design separates module composition from projection storage and attention backend selection. Architecture constructors assemble the blocks; Linear selects a weight implementation; Attention retains the same projection and rotary pipeline across cached and uncached execution. [source; call_15326ae372f14506841a44dbf3171ec0, call_c75755c132d5415ba1f1ba26d39baabe, call_fce3285be7144390b6bcf32cd83aad28]

## Impact

The change introduces the module API and implementations for embeddings, linear projections, RMS normalization, attention, ordinary and gated MLPs, and transformer blocks. [source; call_ac5f19fcfbbb419a815a01d90e8fdcc5]

## Transformer composition, attention and rotary execution

Composition and device boundaries. Module is a custom abstract base, not a torch.nn.Module subclass. It registers children explicitly, recursively loads and unloads them, traverses itself before descendants, and aggregates quantization labels and weight counts. prepare_for_device moves an activation to the module's device. Model.forward runs top-level modules sequentially under inference_mode, moving the state at each boundary. The inspected Llama constructor demonstrates the interface: embedding → transformer blocks → final RMSNorm → vocabulary projection, with prepare_inputs calling prepare_for_attn. Architecture-specific assembly belongs to the models chapter. [source; call_7da38eeaee9e439d95a96fcf2314bc71, call_95ea20f830b944959bbee294c3f6f110, call_15326ae372f14506841a44dbf3171ec0]

Embedding and residual precision. Embedding maps token IDs to hidden vectors, defaults its output to float32, marks itself as preferring CPU placement, and rejects a quantization map. Loading converts float32 weights to half, rather than universally converting every weight dtype. Its optional normalize operation multiplies embeddings by sqrt(hidden_size); it is not unit-length normalization. The shared to2 helper gives an explicit forward-call dtype precedence over the module default, otherwise preserving the tensor dtype. [source; call_bb3a38ce9e3d4868a825142925c44187, call_5b063db097b14b8da3a2475e47b31b55]

TransformerBlock.forward implements two sequential residual branches. Starting with x, it computes attention from attn_norm(x), optionally normalizes the attention output, and adds it to x in place. It then computes the MLP from mlp_norm(updated x), optionally normalizes that output, and adds it in place. Both input normalizations explicitly request half output, while the residual stream retains its existing storage dtype. The post-normalizations are optional; despite optional constructor annotations, the two input norms, attention and MLP are called unconditionally. [source; call_da3a47a6b09e4f9f9a78198c04ce4b42]

Prefill is a targeted execution shortcut, not a different attention formula. Model.prefill marks only the last cache-affecting top-level module with params['prefill'] and stops after it. TransformerBlock checks that flag after attention has executed, returning the incoming residual without the attention addition or MLP. Earlier blocks still execute normally because their outputs feed later keys and values. The last attention call still includes its output projection. The shared params dictionary is mutable: prefill leaves its flag set, and Model.forward does not clear it. [source; call_95ea20f830b944959bbee294c3f6f110, call_da3a47a6b09e4f9f9a78198c04ce4b42, call_fce3285be7144390b6bcf32cd83aad28]

Linear is the storage-independent projection interface. Loading tries EXL3 tensor groups across the primary and optional alternate keys before trying ordinary weights. Ordinary fused weights can be sliced by output-row ranges into separate logical projections; this does not fuse their forward calls. EXL3 loading passes trellis data, scaling/transform tensors and optional bias to LinearEXL3. forward delegates to the selected inner implementation and can then apply an in-place output softcap, c·tanh(x/c); zero disables this operation. The quantized-inference chapter covers the inner projection kernels. [source; call_c75755c132d5415ba1f1ba26d39baabe, call_bcedd362e436414f84fa4244a0ce27d0]

The conversion interface follows activation identity. Attention gives Q/K/V the same qmap suffix, and GatedMLP gives gate/up the same suffix, because each group consumes the same input. Linear.capture_H flattens leading dimensions into token rows, copies them to float32, accumulates XᵀX, and increments a row count. A first_key guard prevents another projection sharing that label from accumulating the same input again. convert_exl3 extracts weights and bias, drops the original inner layer, invokes quantize_exl3 with Hessian data, and installs a LinearEXL3 while preserving bias. This is the local handoff to the conversion and quantizer subsystems, not an accuracy measurement. [source; call_7da38eeaee9e439d95a96fcf2314bc71, call_c75755c132d5415ba1f1ba26d39baabe, call_fce3285be7144390b6bcf32cd83aad28, call_26adf7b7b18a4081ab25a66a8a8b5279]

Attention shapes. For input [B,T,H], projections produce Q of width Nq·D and K/V of width Nkv·D, then reshape to [B,T,Nq,D] and [B,T,Nkv,D]. RoPE modifies Q/K, not V. Attention output is flattened back to [B,T,Nq·D] before the output projection restores width H. A fused QKV checkpoint is interpreted as consecutive Q, K and V output-row ranges of those widths. Unequal head counts set the GQA flag; SDPA receives enable_gqa, while FlashAttention receives the differing head dimensions directly, with no explicit Python replication of K/V. [source; call_fce3285be7144390b6bcf32cd83aad28]

Three attention routes share these projections. flash_attn_nc is the default; it rotates Q/K in place and calls flash_attn_func with causal masking enabled by default, the configured softmax scale, a symmetric window tuple, and attention-logit softcapping. flash_attn uses the corresponding KV-cache function. sdpa_nc instead transposes tensors to [B,heads,T,D], calls torch scaled_dot_product_attention, and transposes back. It rejects a nonnegative sliding_window and nonzero logit_softcapping, and omits sm_scale from its call. Both no-cache preparation functions reject a supplied cache. Here -1 is the default unrestricted-window sentinel, and 0.0 disables attention softcapping. [source; call_fce3285be7144390b6bcf32cd83aad28]

Cache preparation turns a conventional batch into a page table. Given batch_shape, prepare_flash_attn checks batch capacity, requires exactly one of past_len or cache_seqlens, and requires cache sequence capacity to be divisible by PAGE_SIZE=256. It builds consecutive page indices reshaped to [B,capacity/256]. A scalar past_len is expanded to int32 sequence lengths and supplies the default rotary offset; per-sequence lengths supply default rotary positions unless positions or explicit position_ids are provided. An already-paged caller supplies block_table and cache_seqlens directly. These functions do not themselves schedule chunks or advance sequence lengths. [source; call_fce3285be7144390b6bcf32cd83aad28, call_f5f53c8bc09748278e29ff8f8b1140d8]

Cache ownership and attention handoff. Cache attaches layer objects to modules advertising kv_cache; Attention.load allocates those objects on its own device and unload frees them. The default FP16 layer stores each of K and V as [max_tokens/256,256,Nkv,D]. decode_flash_attn retrieves storage by layer_idx and passes it, freshly rotated K, V, block_table and cache_seqlens to flash_attn_with_kvcache. Thus cache mutation is delegated to the external attention call, while this wrapper performs no explicit length increment or writeback. Attachment traversal and attention layer indices must agree. The generation chapter owns the scheduling side of that interface. [source; call_1031f039ce3040ec966cb984b8184492, call_37590878a92642239eb439674e389b44, call_fce3285be7144390b6bcf32cd83aad28]

Per-device metadata is cached inside params. Attention uses get_for_device for page tables, lengths and positional tensors. That helper memoizes each key/device conversion and explicitly assumes values remain read-only for the dictionary's lifetime. Consequently, replacing positional or cache-length metadata while retaining dev_cache can reuse stale device values; callers need a fresh dictionary or appropriate invalidation. [inference; call_fce3285be7144390b6bcf32cd83aad28, call_5b063db097b14b8da3a2475e47b31b55]

A bounded integer check verified the conventional-batch page layout: for B=2, capacity=512, page size 256, two KV heads and head dimension 8, all 16,384 element offsets from the generated page table matched the corresponding contiguous [B,capacity,Nkv,D] offsets. This verifies that indexing identity for the example, not FlashAttention's implementation or cache lifecycle. [execution; call_891e21e9ed5441bda720b09ca96c950f]

RoPE construction. With rotary dimension d=int(head_dim·partial_rotary_factor), the default inverse frequency for pair i is theta^(−2i/d), with default theta=10000 and attention factor 1. NEOX pairs channels i and i+d/2. For angle position·frequency, the CUDA kernel computes (u·cos−v·sin, v·cos+u·sin), using float intermediates and rounding outputs to half. The attention factor multiplies both sine and cosine. A scalar starting position uses token_index+position; per-sequence positions use token_index+positions[batch]; explicit position_ids supplies each token position directly. The native wrapper prohibits supplying both positional tensors. [source; call_84c531605ab2472fa94cc1f177b43724, call_3b92d460ae3f477fba5fd5f7a2d35b5a, call_50c85198ef6847d29a6f785ea15ee3d9]

RoPE scaling alternatives are implemented as frequency construction, not separate attention kernels. Linear scaling divides every frequency by its factor. Llama3 scaling compares wavelength 2π/frequency with old_context/high_freq_factor and old_context/low_freq_factor: short wavelengths retain their frequency, long wavelengths divide it by factor, and the middle band blends between them. Its fallback values are factor 8, low/high factors 1 and 4, and old context 8192. YaRN blends original and divided frequencies using a clamped ramp whose bounds come from rotation counts over the configured context; beta_fast=32 and beta_slow=1 are those default counts. Its default amplitude is 1+0.1·log(factor), and 0.001 prevents division by zero when ramp bounds coincide. LongRoPE/su selects per-frequency long or short factors according to the effective context override, but computes its amplitude sqrt(1+log(a/b)/log(b)) from configured maximum a and original maximum b when a>b. [source; call_84c531605ab2472fa94cc1f177b43724]

Rotary implementation tradeoff. RoPE.apply makes inputs contiguous and calls a kernel that computes sine/cosine directly for each token; the kernel grid spans sequence and batch, and its head parallelism is bounded by 1024 threads per block. The alternative apply_torch maintains half-precision sine/cosine tables, expanded in 2048-position increments, and applies duplicated NEOX coefficients through _rotate_half. This trades cached coefficient storage against repeated trigonometric computation, but no timing comparison establishes which wins. The 2048 coefficient-growth interval is unrelated to the 256-token KV-cache page size. [inference; call_84c531605ab2472fa94cc1f177b43724, call_3b92d460ae3f477fba5fd5f7a2d35b5a, call_f5f53c8bc09748278e29ff8f8b1140d8]

Scalar rotary checks covered 24 combinations of head dimensions 8/64/128, positions 0/1/255/8192 and amplitude factors 1/1.25. Rotating Q and K at the same position preserved their dot product multiplied by amplitude², with maximum double-precision error 7.11×10⁻¹⁵. Integer analysis also confirmed that the NEOX rotation/copy destinations cover a 128-channel head exactly once for rotary dimensions 128 and 64. In the partial case, however, 32 of the kernel's 64 unconditional frequency indices exceed the 32-element frequency array. [execution; call_891e21e9ed5441bda720b09ca96c950f]

The partial-RoPE indexing result exposes a source-level safety concern rather than a demonstrated GPU failure: rope_kernel reads inv_freq[threadIdx.x] before testing whether that thread rotates a pair or merely copies unrotated channels. A partial frequency array can therefore be shorter than the launched frequency-index range. Separately, the Torch alternative applies full-vector _rotate_half and coefficient multiplication without explicitly separating an unrotated tail, so it should not be treated as a validated partial-RoPE fallback. [inference; call_3b92d460ae3f477fba5fd5f7a2d35b5a, call_84c531605ab2472fa94cc1f177b43724, call_891e21e9ed5441bda720b09ca96c950f]

RMSNorm reduces over the last dimension without subtracting a mean: y_i=x_i·(w_i+constant_bias)/sqrt(mean(x²)+epsilon). Python flattens leading dimensions into rows and restores the original shape afterward. The native implementation uses float accumulation, fused multiply-add square sums and reciprocal square root; half inputs pass through its clamp helper. Four-element vector loads explain the required width divisibility by four, while 1024 threads are a launch choice rather than a normalization parameter. The Torch alternative casts normalized values back to the input dtype before weight multiplication, unlike the native float-intermediate path, so identical formulas do not imply bitwise-identical results. [source; call_a67ebc4c0d62497497ec95ea00d7ef20, call_ef3ecc67fa37464f8404b0b6a7e2e929]

MLP execution preserves leading batch/sequence dimensions while expanding hidden width H to intermediate width I and projecting back. MLP computes down(silu(up(x))). GatedMLP instead computes down(activation(gate(x))·up(x)), with SiLU or GELU selected at construction. A fused gate/up checkpoint is sliced into [0,I) and [I,2I), but gate and up still run separately. The activation/multiply kernel writes directly over the up result using half2 pairs. SiLU uses half exponential/reciprocal arithmetic; GELU uses the tanh approximation with sqrt(2/π)≈0.797884560803 and cubic coefficient 0.044715, then rounds to half before multiplication. [source; call_26adf7b7b18a4081ab25a66a8a8b5279, call_c75755c132d5415ba1f1ba26d39baabe, call_1a8596f5c2f74ea48adc339bc546edf1]

## Uncertainty and limits

No model execution, CUDA kernel test, FlashAttention integration test or performance measurement was performed. The bounded Python checks validate scalar algebra and integer indexing, not FP16 rounding, CUDA fast trigonometry, reduction ordering or device memory safety.

RoPE support is incomplete: the CUDA GPTJ branch is a TODO, NONE launches no rotation kernel, and apply_torch also flags GPTJ as unfinished. Partial rotary dimensions expose an unconditional frequency-read bounds concern; its runtime consequences were not tested.

The SDPA route is not interchangeable with the FlashAttention routes for every configuration: it rejects sliding windows and attention softcapping, and does not pass the configured sm_scale. Q/K normalization remains a TODO in all three attention routes.

The native paths have narrower contracts than generic tensor APIs: RoPE requires FP16 Q/K; RMSNorm expects half weights and float/half activations; gated activation kernels operate on half2 pairs without validating dtype or handling an odd trailing element.

The inspected source supplies RoPE scaling formulas and defaults, but does not establish the empirical rationale or optimality of constants such as YaRN's 0.1 attention-factor coefficient and rotation thresholds.
