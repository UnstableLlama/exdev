## Problem

The perplexity loop retains its `input_ids` reference after preparing targets and does not explicitly release allocator cache at each iteration. Its progress display also lacks a final update.

## Reasoning

Deletes the input reference after creating shifted targets, empties the CUDA allocator cache after deleting intermediate scoring tensors, and updates the progress bar to the completed row count. The target shift, log-softmax, gather and averaging formulas are unchanged. Deleting a tensor name does not guarantee freeing its storage when a view or another reference remains; the shifted target can share storage depending on the device conversion.

## Impact

Changes transient memory handling and progress reporting in the comparison evaluator. It does not establish a measured reduction in peak memory or an improvement in perplexity.
