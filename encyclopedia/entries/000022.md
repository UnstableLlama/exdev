## Problem

Conversion emits per-linear metrics and a separate module message but lacks a remaining-time estimate and a reusable progress task transition.

## Reasoning

Times each processed module, combines bitrate and state-error reporting, and estimates remaining time from the latest module duration times the remaining module count. This is a simple heuristic, not an average or architecture-aware forecast. Adds human_time formatting and switches the quantizer from two progress contexts to a task reset within one context.

The new human_time rounds hours before subtracting them from minutes. Executing that exact added function for 1,800 seconds produces `1 hour, -30 minute`. This is a concrete formatting defect in the new code; the Encyclopedia preserves it rather than correcting the source.

## Impact

Improves conversion feedback and progress continuity in intent, with potentially misleading time formatting and an estimate that assumes remaining modules cost roughly the same as the latest one. No new quantization formula or storage schema is introduced.
