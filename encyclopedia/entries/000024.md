## Problem

Conversion selects cuda:0 and each tile-quantization batch runs on one device. The parent LDLQ loop contains a TODO about splitting tile work across GPUs.

## Reasoning

Adds a comma-separated devices option, uses the first selected device for the main conversion work and passes the list through quant_args. The new quantize_tiles_multigpu stages input tiles in pinned host memory, splits the batch across selected GPUs, launches work on cached per-device streams and gathers reconstructions and indices back to the first device. Events order the host copy, per-device work and final gather. Single-device use returns through the existing tile routine. A separate synchronous variant is added but the modified LDLQ and scale-search callers select the asynchronous variant.

Temporary Viterbi buffers are now cached by device and K, and pinned host buffers grow for larger batches. The LDLQ outer loop and error-compensation state remain on the main device; independent tile batches are what get distributed. Golden-section scale evaluations use the same multi-GPU routine. Blockwise RMS/error helper defaults increase from 16 to 32.

The added progress expression is `100 - 100 * int(delta2 / delta1)`. After the first strict interval shrink, the ratio lies between zero and one, so integer truncation makes the displayed value 100 immediately. This is a source-level progress issue, independent of numerical quantization correctness.

## Impact

Introduces multi-GPU conversion work distribution, not tensor-parallel inference. It adds stream/event and persistent-buffer lifetime requirements, plus host staging traffic. Speedup depends on workload and transfer costs; the commit alone cannot establish scaling or equivalence across devices.
