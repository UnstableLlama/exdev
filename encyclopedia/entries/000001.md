## Reasoning

The initial tree separates architecture configuration and model assembly from reusable modules, weight loading, generation, and quantization. `Config.from_directory` dispatches through `models/architectures.py`; the registry contains Llama, Mistral, Qwen2, Phi3 and Gemma2 classes. `Model.load` supports single-device and layer-split loading, but explicitly raises NotImplementedError for tensor parallelism. A planned capability must not be mistaken for an implemented one.

`conversion/convert_model.py:main` walks modules, captures calibration Hessians, allocates bitrates, converts linear layers, writes intermediate tensors, advances calibration state and checkpoints. `quantize_exl3` regularizes weights with channel scales and random signs, applies Hadamard transforms, searches a global scale, invokes `ldlq`, and emits `suh`, `svh`, and packed `trellis` tensors. `ldlq` processes 16-by-16 tiles with error compensation; it permutes tiles into tensor-core layout before quantization and reverses that permutation only for reconstructed weights. The encoded representation retains the execution layout.

The QTIP paper's trellis quantizer maps to `quantize_tiles` and its extension call; its blockwise error feedback maps to `block_ldl` and `ldlq`. This is an algorithm-level mapping, not a claim that every equation is proven equivalent. At the pinned QTIP revision, `lib/algo/ldlq.py:LDLQ` also uses reverse block traversal, error feedback and a 256-element kernel permutation. Its `bitshift_codebook` offers several decoder modes and Python/PyTorch Viterbi operations. EXL3's wrapper instead invokes a fused extension and packs each 256-weight tile into `256*K/16` 16-bit words. The initial EXL3 documentation explicitly identifies regularization and packing as departures. The performance advantage is asserted by the author, not independently measured here.

## Impact

This commit establishes both the inference stack and the converter, including examples, CUDA extension code, calibration data, evaluation specifications and tests. The first structural snapshot is therefore appropriate here. The README explicitly lists cache quantization, multimodal support, LoRA, ROCm, additional samplers and tensor parallelism as unfinished. The listed architecture classes establish dispatch support, not proof that every model in those families loads correctly.
