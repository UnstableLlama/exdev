## Main data flow

Configuration loading reads the model directory's `config.json`, requires one architecture, and dispatches to an architecture-specific config. That config prepares safetensors access. A model is constructed from the config, populated with modules and loaded on one device or split by layer across devices. Tokenized inputs pass through the module tree; generation adds cache management and token sampling. The final sentence describes the composition implied by the module layout, not an executed end-to-end test.

Conversion has a separate module-by-module flow. It loads the source model, creates or resumes calibration state, runs a module while capturing Hessians, assigns bitrates to quantizable linears, converts them and writes their tensors. Calibration activations then advance through the converted module. Checkpoint directories store progress and activations; final compilation assembles output files. This design avoids requiring all unquantized modules on the GPU at once, although peak memory still depends on each module and quantizer buffers.

The core quantizer applies scales, random signs and Hadamard transforms, computes a block LDL factor, compensates previously introduced quantization error, and quantizes 256-value tiles. It stores packed trellises and two channel-scale tensors. Quantization layout is coordinated with tensor-core execution layout.
