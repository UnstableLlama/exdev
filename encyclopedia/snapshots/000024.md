# Snapshot at commit 000024

Commit: `72e88aef02ac18ef080f3cc084bac6109553d322` (2025-04-09).
Evidence: entries 000001–000024, the parent source and the current diff. No later commit is used.

The main structural change since [snapshot 000018](000018.md) is multi-GPU **conversion**. The converter parses `--devices`, keeps the main module and error-feedback work on the first selected device, and distributes independent batches of 256-value tiles across GPUs. Both LDLQ tile quantization and scale-search evaluations call the new distribution routine. This does not implement tensor-parallel inference or distribute the entire Hessian/LDL computation.

The asynchronous path stages input in reusable pinned host buffers, waits on an input-copy event, quantizes slices on cached device streams, stages results back to host, and gathers them on the primary stream after completion events. Viterbi scratch buffers are cached by device and bitrate. A synchronous alternative exists but is not selected by the modified callers. One-device requests bypass distribution.

The original architecture registry remains unchanged in this interval. The metadata sidecar now consistently recognizes lowercase exl3 following entries 000019–000020. Conversion reports per-module time and an estimated remaining duration. Several explicit garbage-collection/cache-flush calls have been removed.

Open issues visible at this point include the time formatter's negative-minute behavior already demonstrated in entry 000022, a new progress calculation that jumps to 100 after the first interval shrink, unknown multi-GPU numerical/performance behavior, and persistent buffer/stream reuse assumptions. No multi-GPU test was run. The initial-source provenance gaps also remain open. These are as-of observations, not predictions of later fixes.
